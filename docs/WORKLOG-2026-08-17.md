# AnchorClaw worklog — 2026-08-17

## Goal

Restore package compatibility across supported OpenClaw releases and audit the
full memory-injection path after reports that long-running conversations,
especially role-play conversations, had started sticking to stale context.

## Completed

### OpenClaw and ClawHub compatibility

- Raised the package version from `0.1.3` to `0.1.4`.
- Removed runtime imports of the deleted
  `openclaw/plugin-sdk/memory-core-host-engine-qmd` export.
- Added a frozen local legacy session-file adapter for supported older hosts.
- Kept legacy transcript indexing/search on older OpenClaw releases.
- Delegated transcript search to native `sessions_search` and
  `sessions_history` on OpenClaw `>=2026.8.1-beta.1`.
- Updated status output, tests, architecture notes, installation docs, README,
  manifest metadata, and changelog for the split legacy/native behavior.
- A preliminary ClawHub validation against `2026.8.1-beta.2` passed with zero
  breakages. The only remaining finding was the known P2 warning for the
  top-level `uiHints` field.

### Durable-memory injection fix

- Confirmed the regression originated when the asynchronous multi-workspace
  projection was moved from the memory capability builder into a
  `before_prompt_build` hook.
- The hook incorrectly returned `prependContext`, placing virtual `MEMORY.md`
  data in the current user message on every turn.
- Changed durable facts/notes projection to `prependSystemContext`, restoring
  the original system-memory semantics.
- Kept durable projection enabled on continuation turns; this matches the
  intended virtual `MEMORY.md` design and does not introduce RP-specific or
  search-only memory scopes.

### Daily-memory and extractor hardening

- Kept recent daily memory in `prependContext`, matching OpenClaw startup
  context: it belongs to the first user turn, not the system prompt.
- Daily injection still skips continuation turns.
- Escaped triple-backtick sequences inside untrusted daily content exactly as
  OpenClaw core does, preventing stored text from closing its quoted fence.
- Prevented maintenance source text from spoofing the extractor's trusted
  `BEGIN_UNTRUSTED_DAILY_MEMORY` and `END_UNTRUSTED_DAILY_MEMORY` boundaries.
- Added support for the stable startup-context controls available in the
  minimum supported OpenClaw version:
  - `enabled`
  - `dailyMemoryDays`
  - `maxFileChars`
  - `maxTotalChars`
- Preserved core-compatible defaults and clamp bounds when these settings are
  absent, so older configurations retain their previous behavior.
- Removed newly introduced `any` types from the durable and daily prompt hooks;
  they now compile against the official `2026.5.28` SDK types.

### Injection parity audit

- Verified core hook merging and final prompt placement in:
  - `2026.5.28` (minimum package/dev version)
  - `2026.7.1` (current server version)
  - `2026.8.1-beta.2` (ClawHub validation target)
- All three versions concatenate `prependSystemContext` and `prependContext`
  independently; one AnchorClaw hook does not overwrite the other.
- Added a plugin-level contract test proving:
  - durable facts/notes occur once in system context on the first turn;
  - daily memory occurs once in user startup context on the first turn;
  - continuation turns retain durable memory but omit daily startup memory;
  - capability guidance does not duplicate stored memory data;
  - prompt caching avoids another durable-memory database query per turn.
- Confirmed the other memory paths do not leak into the main prompt:
  - `memory_search` and `memory_get` return content only through tool results;
  - pre-compaction flush uses its separate core-managed prompt/system prompt;
  - maintenance extraction is a separate LLM call;
  - session capture writes to daily storage and returns no prompt injection.

## Server findings

- OpenClaw is installed on `server-166` and reports version `2026.7.1`.
- The initial read-only inspection found an archive-built AnchorClaw extension
  reporting `0.0.9`, rather than the expected working-tree build. The
  `refactoring` build reporting `0.1.4` was subsequently installed and the
  gateway restarted.
- The initial archive bundle used the broken durable `prependContext` behavior.
  After the `0.1.4` deployment, the user confirmed that the content-sticking
  regression was resolved.
- Server config includes `hooks.allowPromptInjection=true` and
  `agents.defaults.contextInjection=continuation-skip`.
- No explicit `agents.defaults.startupContext` overrides were found, so core
  defaults currently apply.
- Recent daily entries were not present during the read-only inspection, so the
  reported current behavior was not caused by daily startup injection.
- The durable store contains active workspace facts/notes, including scenario
  context. Because the product intentionally treats every active fact/note as
  virtual `MEMORY.md`, those records are global workspace context. Adding
  RP/story/search-only scopes was explicitly rejected as a separate feature,
  not included in this bugfix.
